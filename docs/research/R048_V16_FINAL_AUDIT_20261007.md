## v1.5 defect and v1.6 repair

V1.5's unlabeled outcome partition merged distinct collect-mode field-to-action mappings. V1.6
hashes the canonical sorted-field assignment-to-complete-outcome function, including primary
action, action names, and typed payloads. Exhaustive collect-field permutations for two through
eight fields produced one v1.6 key per genuinely distinct exact mapping and one shared key only for
identical mappings.

## Comparator red team

The adversarial candidate was correct on the first 50 clusters and deliberately wrong elsewhere.

| Input | Result |
|---|---|
| full 2,688-row evaluation | gate false; accuracy delta `-0.535714`; nine failures |
| direct first-400-row subset | rejected: exact 2,688-row canonical cardinality required |
| rewritten subset manifest with fresh hashes | rejected: manifest output count noncanonical |
| subset with original frozen hashes | rejected: panel hash mismatch |
| original full panel and manifest | accepted as canonical and retained the failing gate |

NaN, infinity, out-of-range values, booleans, strings, bad probability sums, missing/extra qids,
overflowing integers, missing predictions, duplicate IDs, unexpected IDs, and ten metadata
mutations all failed closed. Removing panel versions makes the API diagnostic-only and forces the
canonical gate to fail.

## Operational condition

Launch and comparison receipts must supply the literal frozen panel and manifest hashes listed
above. A runtime input must never be treated as the source of its own expected hash.
